## Product

Multi-tenant support desk with AI triage and AI-suggested replies

Self-serve multi-tenant SaaS: companies (tenants) run customer support; customers raise tickets; staff work a queue against SLAs. AI suggests triage and reply drafts; humans decide. Full detail: `docs/constitution.md`.

**Principles you will trip over in code** (constitution §2):

- **Tenant isolation is absolute.** Tenant comes from the JWT only; use `tenant_session()`; every tenant table has forced RLS; every endpoint gets a cross-tenant test. `/t/{slug}` in URLs is for routing only; slug ≠ JWT tenant → 404.
- **AI suggests, humans decide.** No AI action reaches a customer or changes a ticket without a human.
- **SLA clocks are server-side.** Use DB `now()`; never trust client time. Deadlines come from `compute_deadlines()` only (TD-005).
- **Least data in prompts.** Mask PII before any LLM call; LLM calls only via the APIM gateway (ADR-0001).
- **No PII in logs or traces.** Log ids, not content.

**Non-goals (don't build these):** **any email**, **any third-party service except the AI gateway**, attachments, SSO, billing, mobile, AI auto-actions, per-tenant subdomains.

## Stack

FastAPI · SQLAlchemy 2.0 async · Alembic · PostgreSQL + pgvector · Next.js · pnpm + Nx · uv · Azure (eastus2).

## Run, test, gate

```sh
docker compose up -d db                   # local Postgres + pgvector; roles from db/init/
cd backend && uv sync && uv run alembic upgrade head
uv run uvicorn app.main:app --reload      # API on :8000
uv run pytest -q                          # tests + coverage ≥ 80% + architecture tests
cd .. && pnpm install && pnpm dev:web     # web on :3000 (proxies /api → :8000)
pnpm typecheck && pnpm test
uvx pre-commit run --all-files            # local gate; pre-push runs automatically
```

## Where things go

| Thing | Place |
|---|---|
| A backend feature | `backend/app/features/<feature>/{router,schemas,service,models}.py`; routers never import SQLAlchemy |
| Tenant data access | `app.core.db.tenant_session(tenant_id)`, never a raw session |
| A tenant-owned table | model uses `TenantOwned`; migration calls `migrations.rls.enable_rls()` |
| Errors | raise `app.core.errors.ProblemError` (RFC 7807) |
| Cloud SDK code | `backend/app/adapters/` only |
| Web feature | `apps/web/src/features/<feature>/` |
| Generated API client | `packages/core/src/generated/` (never hand-edit) |
| LLM prompts | `prompts/<feature>/<name>.md` (versioned files) |
| Specs, designs, tasks | `docs/specs/<ID>-<slug>/` |
| Decisions | `docs/adr/NNNN-*.md` |

## Tests

- Acceptance tests come first and are human-reviewed (`acceptance-tdd`). Names contain the AC ID, e.g. `test_td007_ac3_...`.
- Every endpoint has a cross-tenant test.
- Tests run as the runtime app role, so RLS is real in tests too.

## ADRs

| ADR | Decision |
|---|---|
| [0001](docs/adr/0001-azure-apim-ai-gateway.md) | Azure APIM AI gateway instead of LiteLLM; per-tenant token caps keyed on a server-set header |
| [0002](docs/adr/0002-self-issued-jwt-auth.md) | Self-issued JWT (EdDSA, 15 min) + rotating hashed refresh tokens; identity per tenant; no MFA in v1 |
| [0003](docs/adr/0003-multi-tenancy-rls.md) | Shared DB, `tenant_id` + forced RLS, runtime role without BYPASSRLS, per-tenant loops in jobs |
