## Decisions
- Signup = ONE transaction: create_tenant() + set_config(app.tenant_id) + admin + verify token; email sent after commit. A failed step leaves no orphan tenant (tested)
- Reserved slugs are checked in the service (422); the DB regex only checks format
- Resend always returns the same 202 body; only unverified, active users get an email (TM-015)
- New dependencies proposed in this PR: argon2-cffi (MIT), email-validator (Unlicense), httpx moved from dev to runtime (BSD)

- [review] Email sender: in-memory outbox only when environment=local; otherwise get_email_sender() raises (no silent no-op in deployed envs)
- [review] Token issue locks the user row (SELECT … FOR UPDATE): concurrent resends serialise (test with 5 parallel resends)
- [review] IntegrityError mapped by driver constraint_name, not message text
- [review] Resend runs as a background task after an upfront tenant check, so response time doesn't depend on whether the account exists (TM-015)
- [review] Token expiry built with make_interval(), not an f-string
- [review] Passwords NFKC-normalised before policy, HIBP and hashing
- [review] verify_email does nothing for deactivated users
- **Accepted risk for TL (security #2): HIBP check fails open.** Mitigation now: structured log `security_event=breach_check_unavailable` (alert in M11). Not done: re-check at first login / fail closed after N failures. Needs TL confirmation in PR review.
- **Open threat (security #6): TM-013 scripted signups stays open until T-001-03 adds signup rate limits.**
