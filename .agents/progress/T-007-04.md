# T-007-04: Web breach badge + queue order

**Objective:** show the breach badge (AC-9) and render the API's queue order (AC-3), proven by a Playwright E2E test and an axe check.

## Done
- `breachLabel()` (pure, unit-tested): "First response breached 2h ago". It's text, not colour, and shown only while `breach.active`.
- Minimal login and queue pages. The token is kept in sessionStorage, a course simplification (httpOnly cookie in M8).
- `scripts/e2e_seed.py`: a fresh tenant, the flag on, one ticket made overdue and swept, and one calm ticket. The password is random per run.
- `apps/web/e2e/queue.spec.ts`: AC-3 order, AC-9 badge, axe (no serious/critical), and wrong-password error. 3/3 pass locally.
- Mutation check: removing the badge render makes the AC-9 test fail.

## Decisions
- E2E runs against `next build && next start`, not `next dev`. The Next 16 dev server blocks HMR on 127.0.0.1, so pages never hydrated, and a production build is what users get anyway.
- No TanStack Query yet. There are two fetches on two pages, so a plain `fetch` wrapper is enough. Revisit when the web slice grows.
- New dev dependencies: `@playwright/test` 1.64.0 (Apache-2.0) and `@axe-core/playwright` 4.13.0 (MPL-2.0, used unmodified as a test tool).
