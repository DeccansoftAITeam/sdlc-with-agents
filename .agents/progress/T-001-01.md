Expand-only migration for TD-001: tenants registry, users (per-tenant identity), refresh tokens (rotating families), email tokens (verify/reset). RLS forced on every tenant-owned table (ADR-0003).

## Decisions
- Text + CHECK instead of varchar (squawk prefer-text-field)
- Composite FK (tenant_id, user_id) on token tables: DB rejects cross-tenant references even if app code is wrong
- DB-side `gen_random_uuid()` defaults: found when a raw-SQL test insert failed; Python-only defaults break non-ORM writers
- Added test_models_match_migrations: it immediately caught 2 indexes present in the migration but missing from the models

- [review] RLS tests parametrized over all three tenant tables (code-reviewer #1)
- [review] **Tenant is resolved from the URL slug via `resolve_tenant_slug()` BEFORE any token lookup** (refresh, verify, reset all live under `/t/{slug}/…`). Token tables are only read inside `tenant_session`. No system-session token lookups (code-reviewer #2)
- [review] Round-trip test uses the shared DB, so the suite stays serial (no xdist) (code-reviewer #3)
- [review] `tenants`: REVOKE ALL from the runtime role; access only via SECURITY DEFINER `resolve_tenant_slug()` / `create_tenant()`; slug immutability trigger (security #1)
- [review] FK users.tenant_id → tenants.id ON DELETE RESTRICT (security #2)
- [review] Partial unique index: one live email token per (user, purpose); services must consume the old token before issuing a new one (security #3, TM-014)
- [review] CHECK expires_at > created_at on token tables; family-revocation test lands with T-001-03 (security #4)
