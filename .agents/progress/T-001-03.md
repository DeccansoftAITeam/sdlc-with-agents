## Decisions
- Ephemeral signing key only when environment=local; any other environment requires `jwt_private_key_pem` (Key Vault in M9)
- Family revocation is committed BEFORE the 401 (raise after the transaction closes)
- Rate limits are in-process (one replica in v1); must move to Postgres/Redis before scaling out (M10 note)
- Client IP = request.client.host. Behind Next.js/ACA this needs X-Forwarded-For handling from a trusted proxy (M10 note)
- Access tokens aren't re-checked against `is_active` for their 15-minute life (stateless JWT trade-off, ADR-0002)
- TD-001/AC-10 deferred (no reset links in v1); signup limit closes TM-013

- [review] In-memory signing key needs BOTH `JWT_EPHEMERAL_KEY=true` and `ENVIRONMENT=local`; key checked at startup (fail fast)
- [review] JWT carries and requires `iss`/`aud`
- [review] Rate-limit buckets bounded (100k keys, oldest evicted) and pruned when empty
- [review] Per-email login failures counted BEFORE the password check (atomic), undone on success
- [review] Signup limit counts only successful signups (3 typos don't lock anyone out)
- [review] AC-8 amended to name the 20/IP/min login limit
- **Accepted trade-off:** anyone can lock an email out for 1 minute with 5 bad passwords (per-email limit). Mitigated by the short window; CAPTCHA/backoff is v2
- **Accepted trade-off:** two tabs refreshing at the same instant look like token reuse and log the user out (serialised by FOR UPDATE, proven by test). A grace window is v2
