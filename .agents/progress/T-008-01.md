# T-008-01: LLM adapter

**Objective:** one port to a language model, with OrcaRouter and direct Anthropic behind it (ADR-0004).

## Done
- `app/adapters/llm/`: `port.py` (`LLM`, `Completion`, `LLMError`), `orcarouter.py`, `anthropic.py` (plain httpx, no SDK), `fake.py`, `factory.py` (provider and model ids from settings).
- Settings: `ai_enabled` (default off), `llm_provider`, keys as `SecretStr`, model overrides, 10 s timeout.
- Contract tests for both adapters with `httpx.MockTransport`, no network: text and usage, HTTP 429/500, bad shapes, timeout. Errors never carry the key or the provider's response body, and the key isn't in logs or `repr`.
- Architecture test: only `app/features/ai` may import `app.adapters.llm`. A mutation check confirmed it fails on a stray import.
- Manual live check: OrcaRouter → Haiku 4.5 answered, 14 input / 4 output tokens.

## Decisions
- Errors keep only the HTTP status, because a provider's error body can echo the request (ticket text).
- `ai_enabled` defaults to false, so a key in `.env` alone never turns AI on.
