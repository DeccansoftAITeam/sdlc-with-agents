## Decisions
- Users table stays in the auth feature; users/models.py only registers the shared audit table with the ORM metadata
- Role change / deactivation revokes all the user's refresh tokens (old role can't be refreshed); access tokens live at most 15 min
- Last-admin check locks all active admins (FOR UPDATE) so two admins can't demote each other concurrently
- Registration limit: 5 successful registrations per IP per tenant per hour

- [review] require_admin re-checks role + is_active in the DB: a demoted admin loses admin powers immediately, not after 15 min
- [review] Every registration attempt counts (atomic hit), so 409 "email taken" probing is limited to 5/IP/tenant/hour. Residual: an attacker with many IPs can still learn whether an email is a customer of a tenant (TM-015 residual risk; no email channel exists to hide it)
- [review] Admin-created user + its audit row commit in ONE transaction
- [review] Admin rows locked in id order (no deadlock); concurrency proven by test
- [review] Migration refuses to run if the runtime role is missing or equals the owner (append-only guarantee can't silently target the wrong role)
- [review] Spec AC-3 path aligned to the implemented `/t/{slug}/auth/register`
